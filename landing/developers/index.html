Developer Guide: Soroban time locks, vesting and time bounds

Copy-paste examples for building on Stellar with @stellar/stellar-sdk 17.x: call the same Soroban smart contracts the Stellar TimeLock wallet uses to time-lock XLM (Stellar Lumens), add cooling-off withdrawals and vesting schedules, and use Stellar's built-in transaction time bounds and claimable balance predicates. Every sample below was run against Stellar testnet.

The wallet is source available at github.com/stellartimelock/stellartimelock-wallet. These examples use throwaway testnet accounts funded by Friendbot. Never paste a real secret key into sample code.

Setup

npm install @stellar/stellar-sdk@17

Save this as common.mjs. The other samples import from it.

import { Keypair, Networks, contract } from "@stellar/stellar-sdk";
export const RPC_URL = "https://soroban-testnet.stellar.org";
export const NETWORK = Networks.TESTNET;
export async function fundedKeypair() {
  const kp = Keypair.random();
  const r = await fetch(`https://friendbot.stellar.org?addr=${kp.publicKey()}`);
  if (!r.ok) throw new Error("friendbot failed: " + r.status);
  return kp;
}
export async function vaultClient(contractId, kp) {
  const { signTransaction } = contract.basicNodeSigner(kp, NETWORK);
  return contract.Client.from({ contractId, rpcUrl: RPC_URL, networkPassphrase: NETWORK, publicKey: kp.publicKey(), signTransaction });
}
export const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

Send XLM with a memo

Exchanges and many services need a memo to credit you. Memo.text holds at most 28 bytes (bytes, not characters, so emoji count extra); the SDK throws if you go over. 

import { Horizon, TransactionBuilder, Operation, Asset, Memo, BASE_FEE } from "@stellar/stellar-sdk";
import { fundedKeypair, NETWORK } from "./common.mjs";
const horizon = new Horizon.Server("https://horizon-testnet.stellar.org");
const sender = await fundedKeypair();
const receiver = await fundedKeypair();
const memoText = "invoice 1042";
if (new TextEncoder().encode(memoText).length > 28) throw new Error("memo over 28 bytes");
const account = await horizon.loadAccount(sender.publicKey());
const tx = new TransactionBuilder(account, { fee: BASE_FEE, networkPassphrase: NETWORK })
  .addOperation(Operation.payment({ destination: receiver.publicKey(), asset: Asset.native(), amount: "12.5" }))
  .addMemo(Memo.text(memoText))
  .setTimeout(60)
  .build();
tx.sign(sender);
const res = await horizon.submitTransaction(tx);
console.log("paid, hash", res.hash);
const t = await horizon.transactions().transaction(res.hash).call();
console.log("memo on ledger:", t.memo_type, t.memo);
try { Memo.text("x".repeat(29)); console.log("NO THROW on 29 bytes"); } catch (e) { console.log("29-byte memo rejected:", e.message); }

Time-lock vault (xlm_vault)

Testnet contract CBIXRLC5GQ6O5UUJFVRIWZD77P5LUVJG3XGGUVS4EWHAJ6LXQZNKH35Z locks XLM until a Unix timestamp. Functions: create_vault, deposit, extend_lock, withdraw, get_vault, list_owned. The lock can only move later, never earlier, and withdraw fails until the unlock time passes. Amounts are in stroops (1 XLM = 10,000,000). Calls that return Result are unwrapped with .result.unwrap(). 

import { fundedKeypair, vaultClient, sleep } from "./common.mjs";
const VAULT = "CBIXRLC5GQ6O5UUJFVRIWZD77P5LUVJG3XGGUVS4EWHAJ6LXQZNKH35Z";
const owner = await fundedKeypair();
const vault = await vaultClient(VAULT, owner);
const XLM = 10_000_000n; // 1 XLM = 10,000,000 stroops
const now = BigInt(Math.floor(Date.now() / 1000));
let tx = await vault.create_vault({ owner: owner.publicKey(), name: "Rainy day", initial_deposit: 5n * XLM, unlock_timestamp: now + 20n });
const vaultId = (await tx.signAndSend()).result.unwrap(); // contract returns Result<u64>
console.log("vault id", vaultId);
await (await vault.deposit({ caller: owner.publicKey(), vault_id: vaultId, amount: 2n * XLM })).signAndSend();
await (await vault.extend_lock({ caller: owner.publicKey(), vault_id: vaultId, additional_seconds: 10n })).signAndSend();
const v = (await vault.get_vault({ vault_id: vaultId })).result.unwrap();
console.log("balance", v.balance, "unlocks", new Date(Number(v.unlock_timestamp) * 1000).toISOString());
const { result: ids } = await vault.list_owned({ owner: owner.publicKey() });
console.log("owned", ids);
try { await (await vault.withdraw({ caller: owner.publicKey(), vault_id: vaultId })).signAndSend(); console.log("EARLY WITHDRAW WORKED?!"); }
catch (e) { console.log("early withdraw refused:", String(e.message).slice(0, 120)); }
while (BigInt(Math.floor(Date.now() / 1000)) < v.unlock_timestamp + 6n) await sleep(2000);
await (await vault.withdraw({ caller: owner.publicKey(), vault_id: vaultId })).signAndSend();
const after = (await vault.get_vault({ vault_id: vaultId })).result.unwrap();
console.log("withdrawn", after.withdrawn, "balance", after.balance);

Cooling-off and vesting (multi_asset_vault_v2)

Testnet contract CAHAQAN6KYAQCJ34W6CVZJGMWRXKCZFHM32F37E4EFEIIC4636TD74BV holds any token; for XLM pass the native token contract CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC. A cooling-off vault makes every withdrawal wait: call initiate_withdrawal, wait cooling_off_duration_seconds, then withdraw (the owner can cancel_withdrawal in between). A vesting vault releases funds linearly between two timestamps; read get_unlocked_amount and claim with withdraw_vested. 

import { fundedKeypair, vaultClient, sleep } from "./common.mjs";
const V2 = "CAHAQAN6KYAQCJ34W6CVZJGMWRXKCZFHM32F37E4EFEIIC4636TD74BV";
const XLM_TOKEN = "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC"; // native XLM (testnet SAC)
const XLM = 10_000_000n;
const owner = await fundedKeypair();
const v2 = await vaultClient(V2, owner);
const me = owner.publicKey();
const now = () => BigInt(Math.floor(Date.now() / 1000));

// Cooling-off: every withdrawal must be announced, then wait.
let tx = await v2.create_cooling_off_vault({ owner: me, token: XLM_TOKEN, name: "Think twice", initial_deposit: 3n * XLM, cooling_off_duration_seconds: 15n });
const coolId = (await tx.signAndSend()).result.unwrap();
await (await v2.initiate_withdrawal({ caller: me, vault_id: coolId })).signAndSend();
let cv = (await v2.get_vault({ vault_id: coolId })).result.unwrap();
console.log("cooling id", coolId, "kind", cv.kind.tag, "initiated", cv.withdrawal_initiated_timestamp);
while (now() < cv.withdrawal_initiated_timestamp + cv.cooling_off_duration_seconds + 6n) await sleep(2000);
await (await v2.withdraw({ caller: me, vault_id: coolId })).signAndSend();
console.log("cooling-off withdrawn", (await v2.get_vault({ vault_id: coolId })).result.unwrap().withdrawn);

// Vesting: unlocks linearly between start and end.
const start = now();
tx = await v2.create_vesting_vault({ owner: me, token: XLM_TOKEN, name: "Payroll", initial_deposit: 6n * XLM, vesting_start_timestamp: start, vesting_end_timestamp: start + 60n });
const vestId = (await tx.signAndSend()).result.unwrap();
await sleep(20000);
const claimable = (await v2.get_unlocked_amount({ vault_id: vestId })).result.unwrap();
console.log("vesting id", vestId, "claimable", claimable);
await (await v2.withdraw_vested({ caller: me, vault_id: vestId, amount: claimable })).signAndSend();
const vv = (await v2.get_vault({ vault_id: vestId })).result.unwrap();
console.log("withdrawn_so_far", vv.withdrawn_so_far, "of", vv.total_locked_amount);

Time bounds vs. time-lock vaults

Stellar has three different "wait until" tools, and they are easy to mix up:

  • Transaction time bounds (minTime / maxTime) limit when one signed transaction can make it into a ledger. Too early fails with tx_too_early, too late with tx_too_late. They hold no funds: the account can still spend its balance in another transaction. setTimeout() sets maxTime; setTimebounds(min, max) sets both (0 = no bound).
  • Claimable balance predicates move funds into a ledger entry that only the listed claimants can claim, when a predicate is true. NOT(BEFORE_ABSOLUTE_TIME(t)) means "claimable from t", and early claims fail with op_cannot_claim. No contract needed, but no cooling-off or vesting logic.
  • Soroban time-lock contracts such as xlm_vault hold the funds and enforce any rule you can code: extend-only locks, cooling-off withdrawals and linear vesting, lists of vaults per owner.

This sample shows the first two: a payment that is rejected before its minTime and accepted after, and a claimable balance that Bob can only claim after the unlock time.

import { Horizon, TransactionBuilder, Operation, Asset, Claimant, BASE_FEE } from "@stellar/stellar-sdk";
import { fundedKeypair, NETWORK, sleep } from "./common.mjs";
const horizon = new Horizon.Server("https://horizon-testnet.stellar.org");
const alice = await fundedKeypair();
const bob = await fundedKeypair();
const now = () => Math.floor(Date.now() / 1000);
const why = (e) => JSON.stringify(e?.response?.data?.extras?.result_codes ?? e.message);

// 1) Transaction time bounds: this payment is only valid between minTime and maxTime.
const minTime = now() + 15, maxTime = now() + 300;
const tx = new TransactionBuilder(await horizon.loadAccount(alice.publicKey()), { fee: BASE_FEE, networkPassphrase: NETWORK })
  .addOperation(Operation.payment({ destination: bob.publicKey(), asset: Asset.native(), amount: "1" }))
  .setTimebounds(minTime, maxTime) // use instead of setTimeout(); 0 = no bound
  .build();
tx.sign(alice);
try { await horizon.submitTransaction(tx); console.log("EARLY TX ACCEPTED?!"); }
catch (e) { console.log("submitted early:", why(e)); } // {"transaction":"tx_too_early"}
while (now() < minTime + 6) await sleep(2000);
console.log("same signed tx after minTime:", (await horizon.submitTransaction(tx)).successful);

// 2) Claimable balance with a time predicate: Bob can claim only after unlockAt.
const unlockAt = now() + 20;
const cbTx = new TransactionBuilder(await horizon.loadAccount(alice.publicKey()), { fee: BASE_FEE, networkPassphrase: NETWORK })
  .addOperation(Operation.createClaimableBalance({
    asset: Asset.native(),
    amount: "5",
    claimants: [new Claimant(bob.publicKey(), Claimant.predicateNot(Claimant.predicateBeforeAbsoluteTime(String(unlockAt))))],
  }))
  .setTimeout(60)
  .build();
cbTx.sign(alice);
await horizon.submitTransaction(cbTx);
const balanceId = cbTx.getClaimableBalanceId(0);
console.log("claimable balance", balanceId);
const claim = async () => {
  const t = new TransactionBuilder(await horizon.loadAccount(bob.publicKey()), { fee: BASE_FEE, networkPassphrase: NETWORK })
    .addOperation(Operation.claimClaimableBalance({ balanceId }))
    .setTimeout(60)
    .build();
  t.sign(bob);
  return horizon.submitTransaction(t);
};
try { await claim(); console.log("EARLY CLAIM WORKED?!"); }
catch (e) { console.log("claimed early:", why(e)); } // op_cannot_claim
while (now() < unlockAt + 6) await sleep(2000);
console.log("claimed after unlock:", (await claim()).successful);

SEP-7 web+stellar:pay links

A SEP-7 link asks a wallet to prepare a payment the user then reviews and signs. Omit network_passphrase for mainnet. 

import { Networks, StrKey } from "@stellar/stellar-sdk";
function payLink({ destination, amount, memo, msg, network = Networks.TESTNET }) {
  if (!StrKey.isValidEd25519PublicKey(destination)) throw new Error("bad destination");
  const q = [["destination", destination], ["amount", amount]];
  if (memo) q.push(["memo", memo], ["memo_type", "MEMO_TEXT"]);
  if (msg) q.push(["msg", msg]);
  q.push(["network_passphrase", network]);
  return "web+stellar:pay?" + q.map(([k, v]) => `${k}=${encodeURIComponent(v)}`).join("&");
}
function parsePayLink(uri) {
  const m = /^web\+stellar:pay\?(.*)$/i.exec(uri.trim());
  if (!m) throw new Error("not a web+stellar:pay link");
  const p = new URLSearchParams(m[1]);
  return { destination: p.get("destination"), amount: p.get("amount"), memo: p.get("memo"), memoType: p.get("memo_type") ?? "MEMO_TEXT", msg: p.get("msg"), network: p.get("network_passphrase") ?? Networks.PUBLIC };
}
const link = payLink({ destination: "GAEPPLTQ4OIBG4J6DSI33FDYBB7YCKWOT36DNVLNOV65PIVSBAVSGXLS", amount: "12.5", memo: "invoice 1042", msg: "Coffee & cake" });
console.log(link);
console.log(parsePayLink(link));

FAQ

How do I time-lock XLM on Stellar?

Three ways. A Soroban smart contract such as the xlm_vault contract on this page holds the XLM and refuses withdraw() until the unlock timestamp. A claimable balance with a NOT(BEFORE_ABSOLUTE_TIME) predicate lets the listed claimant claim only after a set time. Pre-signed transactions with a minTime time bound can also release funds later, but they need careful sequence-number and signer setup.

What are transaction time bounds on Stellar?

Time bounds are an optional minTime and maxTime (Unix seconds, checked against ledger close time) on a Stellar transaction. Submitted before minTime it fails with tx_too_early; after maxTime it fails with tx_too_late. In @stellar/stellar-sdk, setTimeout(seconds) sets maxTime and setTimebounds(min, max) sets both; a value of 0 means no bound.

What is the difference between time bounds and a time lock?

Time bounds limit when a signed transaction may be included in a ledger; they don't hold any funds, and the account can still spend its balance with another transaction. A time lock holds the funds: a claimable balance predicate or a Soroban contract enforces that nobody can move them before the unlock time.

Can a claimable balance lock XLM until a date?

Yes. Create the claimable balance with the claimant's predicate set to NOT(BEFORE_ABSOLUTE_TIME(unlock time)); claimClaimableBalance fails with op_cannot_claim until then. The creator can list their own account as a claimant to lock funds for themselves. Predicates can't express cooling-off periods or linear vesting; that needs a Soroban contract.

How do I build a vesting schedule on Stellar?

Use a Soroban contract that releases tokens linearly between a start and end timestamp. The multi_asset_vault_v2 testnet contract on this page does that: create_vesting_vault, read get_unlocked_amount, then withdraw_vested. For a schedule you write yourself, the official soroban-examples timelock contract is a good starting point.

How do I call a Soroban smart contract from JavaScript?

With @stellar/stellar-sdk, contract.Client.from({ contractId, rpcUrl, networkPassphrase, publicKey, signTransaction }) loads the contract's interface from the network, so you can call its functions by name and then signAndSend() the transaction. contract.basicNodeSigner gives you signTransaction for a Keypair in Node.

Where do I start building Soroban smart contracts?

Install Rust and the Stellar CLI, then follow the Hello World guide on developers.stellar.org (stellar contract init, stellar contract build, deploy to testnet). The stellar/soroban-examples repository has small reference contracts, including a timelock. This page shows how to call deployed time-lock and vesting contracts from a JavaScript app.

Is the Stellar TimeLock source code public?

The Android wallet is source available under GPL-3.0 at github.com/stellartimelock/stellartimelock-wallet. Contract IDs and WASM hashes are listed there in CONTRACT_REFERENCE.md. The vault contract source is not published, and no third-party audit is claimed, so test on testnet before relying on any contract.
